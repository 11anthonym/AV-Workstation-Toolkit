# AV Workstation Toolkit 1.1.3 RC 6 (unsigned)

AV Workstation Toolkit 1.1.3 adds workstation-to-workstation migration and reusable workstation templates while keeping automatic installation inside the existing exact-ID managed WinGet boundary. RC 6 is an unsigned release candidate for review and pilot testing. It is not the current published release and is not a production-channel build.

## Before you test

- **Unsigned candidate.** Windows SmartScreen or organizational application control may warn about or block the files. Verify the published SHA-256 checksum and release manifest before running them.
- **Standard-user session.** The application refuses elevated startup. An installer chosen by WinGet can display its normal Windows permission prompt.
- **Pilot systems only.** Review the migration inventory and workstation-template behavior against local software policy before wider deployment.

## What to review

- **Workstation migration:** export the old workstation's installed-application inventory, import it on a replacement, and work from one persistent checklist whose completion comes only from fresh detection.
- **Workstation templates:** build intentional workstation baselines with required or optional applications and manual checks. A newer revision preserves progress for retained items; the same or an older revision cannot replace a newer checklist.
- **Installation continuity:** the compiled worker rechecks each exact managed package, can ask consent to close apps through Windows Restart Manager, retries only recognized transient failures, and reports an installation that needs a Windows restart as **Restart required**.
- **Portable-document integrity:** inventories, templates, and saved checklists are strict and bounded on both read and write; malformed identities, repeated manual-check IDs, unknown fields, and oversized content fail closed.
- **Runtime servicing:** App, launcher, and worker carry the centrally reviewed self-contained .NET 10.0.12 runtime.

## Safety boundaries retained

Imported inventories and templates are descriptive data. They cannot grant worker authority. Automatic changes still require the local managed catalog and plan, one package per WinGet invocation with `--id`, `--exact`, and `--source winget`, an independently validated request, and a fresh worker-side policy check. There is no uninstall, generic command runner, local web server, automatic rollback, or security/MDM/VPN/EDR/OS-management path.

## Known limitations

- This candidate is not Authenticode-signed. Hosted signing is prepared but not operationally configured or approved.
- The in-app managed-catalog update feed is not yet published, so the embedded signed managed revision remains in use.
- AV applications without a confirmed Windows detector may remain **Not checked**, **Manual**, or require the intentionally narrow technician-confirmation path.
- An MSI installation test changes the installed product and belongs on a disposable virtual machine. Package QA performs administrative extraction only.

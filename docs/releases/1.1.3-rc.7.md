# AV Workstation Toolkit 1.1.3 RC 7 (unsigned)

AV Workstation Toolkit 1.1.3 adds workstation-to-workstation migration and reusable workstation templates while keeping automatic installation inside the existing exact-ID managed WinGet boundary. RC 7 is an unsigned release candidate for review and pilot testing. It is not the current published release and is not a production-channel build.

## Before you test

- **Unsigned candidate.** Windows SmartScreen or organizational application control may warn about or block the files. Verify the published SHA-256 checksum and release manifest before running them.
- **Standard-user session.** The application refuses elevated startup. An installer chosen by WinGet can display its normal Windows permission prompt.
- **Pilot systems only.** Review the migration inventory and workstation-template behavior against local software policy before wider deployment.

## Changes since RC 6

- **Restart required, as WinGet actually reports it.** The WinGet command line exits 0 for an installer's "restart required to finish" result (MSI 3010) and only prints "Restart your PC to finish installation." RC 6 recognized only the `0x8A150109` code, which the command line doesn't return for that case, so such installs read as plain success. RC 7 recognizes the notice (English WinGet output) and records **Restart required** after a fresh check.
- **Faster multi-app runs.** The worker reuses a plan read after the last installer ran instead of reading a new one before every package: 1 + N full plan reads instead of 1 + 2N, roughly 80 seconds saved on a 15-app update. No package is checked against a plan from before an installer ran.
- **Needs attention.** A run where nothing failed but apps were skipped, open, or waiting for a restart now ends as **Needs attention** in the main window, not **Failed**.

## What to review

- **Workstation migration:** export the old workstation's installed-application inventory, import it on a replacement, and work from one persistent checklist whose completion comes only from fresh detection.
- **Workstation templates:** build intentional workstation baselines with required or optional applications and manual checks. A newer revision preserves progress for retained items; the same or an older revision cannot replace a newer checklist.
- **Open apps:** with an app such as ShareX open in the notification area, an update names it under **Close open apps**; closing it asks the app to close without forcing it, runs the installer, and reopens apps that support it. Windows Installer apps (7-Zip, Notepad++, PuTTY, MobaXterm, GitHub CLI) are now found open too.
- **Installation continuity:** the worker rechecks each exact managed package, settles one that is already current, skips one that can't run now and continues, retries only recognized transient WinGet failures (at most twice), and explains the rest in plain words.
- **Portable-document integrity:** inventories, templates, and saved checklists are strict and bounded on both read and write; malformed identities, repeated manual-check IDs, unknown fields, and oversized content fail closed.
- **Runtime servicing:** App, launcher, and worker carry the centrally reviewed self-contained .NET 10.0.12 runtime.

## Safety boundaries retained

Imported inventories and templates are descriptive data. They cannot grant worker authority. Automatic changes still require the local managed catalog and plan, one package per WinGet invocation with `--id`, `--exact`, and `--source winget`, an independently validated request, and a fresh worker-side policy check. Apps are closed only with consent, only through Windows Restart Manager, and never forced. There is no uninstall, generic command runner, local web server, automatic rollback, or security/MDM/VPN/EDR/OS-management path.

## Known limitations

- This candidate is not Authenticode-signed. Hosted signing is prepared but not operationally configured or approved.
- The in-app managed-catalog update feed is not yet published, so the embedded signed managed revision remains in use.
- WinGet's restart notice is recognized only in English; in another display language such an install is reported as verified without the restart hint.
- Chrome, installed through Google's MSI wrapper, isn't found open; its own updater replaces files while Chrome runs.
- AV applications without a confirmed Windows detector may remain **Not checked**, **Manual**, or require the intentionally narrow technician-confirmation path.
- An MSI installation test changes the installed product and belongs on a disposable virtual machine. Package QA performs administrative extraction only.

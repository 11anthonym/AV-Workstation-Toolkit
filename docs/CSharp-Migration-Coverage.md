## Retained parity and integration coverage after the 14-phase migration

The active dual-engine suite covers 19 managed planning results and 36 focused domain cases. It compares all current statuses: Current, Missing, UpdateAvailable, ManualUpdate, Held, Manual, Inventory, NotDetected, InventoryIncomplete, InventoryUnavailable, CheckUnavailable, Awareness, and Error. It also compares numeric version normalization/comparison and UI sort keys; strict catalog acceptance/rejection and authority; composed profile, priority, exact manufacturer, discipline, role, search, and Quick View filters; and None/Driver/Service/Listener behavior under clear, Windows Update, and CBS reboot states.

Phase 3 adds 37 provider cases: 9 installed-inventory, 7 update-discovery, 10 registry/detector, 4 reboot, and 7 trusted-candidate cases. Canonical comparison is strict for quality/failure classifications, normalized records, per-source availability/counts, package reliability/install/version evidence, reboot reasons, and trust disposition. A separate live read-only harness exercised WinGet resolution/export/update queries, all uninstall-registry views, and reboot signals on the validation host; local software contents are deliberately not golden data.

Phase 4 adds 4 focused presentation cases for composed filters, stable visible order, Missing/Updates selection, retained explicit selection, install/update counts, enabled state, labels, selection summary, Quick View, and reboot warning state. Compiled presentation/coordinator tests cover the larger asynchronous and failure-state surface without launching a mutation.

Phase 5 adds 4 focused read-only surface cases: three representative managed/external/awareness detail records plus one diagnostics snapshot. The comparison keeps identity, provenance, official URI metadata, explicit unknowns, status/inventory quality, catalog counts, reboot reasons, and registry-source status strict. Focused C# tests additionally cover redaction, runtime-provider failure, parent-provider relationships, malicious URI rejection, selected-detail coherence, and non-executing official URI intents.

Phase 6 adds 26 strict action-request cases. Valid Install/Update requests compare ordered and duplicate package IDs, risk acknowledgement, dry-run state, and deduplicated authorized plan IDs. Hostile cases compare semantic rejection for malformed JSON, missing/unknown/wrong-typed fields, unsupported schema, null/malformed request and package IDs, unsupported actions, empty/oversized payloads, action mismatch, held/manual/awareness/inventory-only records, risk acknowledgement, and pending-reboot risk enforcement. Request timestamps, random nonce values, temporary fixture roots, JSON whitespace, and property formatting are omitted because they are not semantic contract fields. The C# parser additionally rejects duplicate JSON property names at parse time; Windows PowerShell 5.1 `ConvertFrom-Json` retains the last duplicate, so this defense-in-depth difference is documented rather than normalized into permissive C# behavior.

Phase 7 adds 27 IPC/file-lifecycle cases covering contained request persistence meaning, canonical request/progress/result/cancel/WinGet-log identity, incremental JSONL progress, successful/failed/cancelled/dry-run final results, cancellation transitions, duplicate-final idempotence, stale/foreign identity, malformed/wrong-typed/unknown/oversized evidence, nested/wrong-extension/foreign-ID paths, and reparse rejection. Semantic output keeps acceptance, artifact kind, record/issue counts, result status, lifecycle state, cancellation state, and package IDs strict. Timestamps, temporary roots, atomic temporary names, computer identity, and JSON formatting are deliberately omitted. Focused MSTest coverage separately proves same-directory atomic write/no overwrite/no residue, bounded reads, reparse checks, split multibyte UTF-8, strict full-schema results, and illegal lifecycle transitions.

Phase 8 adds 8 focused orchestration tests and 4 process-boundary scenarios. They characterize complete-request validation, fresh authorization before every package, still-eligible execution, current/held/action/risk/reboot/unknown rejection, failure and verification-failure precedence, earlier-package effects on later eligibility, cooperative cancellation between packages, correlated progress/result artifacts, clean process exit, and final-result no-overwrite behavior. The retained deterministic fake executor and its bounded delay now live only in the non-shipping `AVWorkstationToolkit.Worker.DevHost`; the production worker contains only real production composition. The process harness runs on a standard-user host and reports an elevated hosted runner as unavailable rather than bypassing the privilege guard.

Phase 9 adds four dual-engine argument cases plus focused trust, exit, timeout, and post-action verification tests. The real executor is present only as an uncomposed Infrastructure implementation. Its public boundary accepts a typed package request, not an executable or argument list; tests inject a capturing process host and prove the trusted resolved path plus exact argument vector without launching WinGet. The Phase 8 process host remains fake-only. Fresh post-action inventory/update quality and package evidence are required before exit zero becomes verified success.

Phase 10 added 15 deterministic vendor-boundary tests. Catalog parsing retains the already validated delivery policy as typed data; callers cannot substitute arbitrary hosts, cache destinations, credential targets, or process arguments. HTTPS redirect handling is explicit, SFTP host identity is probed and compared before a scoped credential lookup, and downloaded payloads remain untrusted until hash/signature/publisher validation and contained promotion succeed. Phase 13 production-composed those services, and Phase 14 retired the launcher bridge.

Phase 11's retained non-shipping integration harness composes the compiled request, IPC, fake-worker, vendor, handoff, and diagnostics boundaries under an isolated temporary root. The coordinator rejects conflicting actions, reauthorizes selection, correlates bounded progress/results, records cooperative cancellation intent, refreshes the typed plan after completion, and never terminates the independent worker on UI shutdown. The exact fake host path resolves to the separately identified non-shipping `AVWorkstationToolkit.Worker.DevHost`; callers cannot supply an executable or argument vector. The production compiled App no longer contains this development activation. Official browser handoffs accept only typed catalog intents, Explorer reveals only reverified cached payloads, and diagnostics copy/export uses sanitized bounded text.

Phase 12's retained standard-user-only development harness accepts only a direct child of the current user's temporary directory named with the `awt-phase12-` prefix. It persists a dry-run request under that isolated root, launches only the reviewed non-shipping development host with a fixed argument shape, composes the real trusted WinGet resolver/read-only providers and mutation executor, releases the caller-side process handle, recovers correlated progress/result evidence through a fresh protocol store, and refreshes current package state. The rehearsal selected an eligible catalogued package but kept `DryRun=true`; no package mutation occurred. No clearly safe managed update was available on the validation workstation, so installing unrelated software solely for rehearsal was rejected.

Phase 13 cut the shipping bootstrap/package to the compiled WPF App, canonical production data root, hash-pinned independent compiled worker, real constrained exact-ID executor, compiled vendor/Credential Manager/cache services, diagnostics, and user handoffs. Phase 14 removed the temporary PowerShell/WPF runtime and launcher vendor bridge from the embedded payload and process policy. The worker is embedded as independently published bytes and extracted beneath the verified versioned runtime; test hosts, test roots, and legacy application-runtime files do not ship.

Post-migration release hardening removed fake and rehearsal activation from all shipping App/Infrastructure/worker assemblies. `AVWorkstationToolkit.Worker.exe` accepts only its exact `--production` invocation and validates canonical production data/application roots. The separate `AVWorkstationToolkit.Worker.DevHost` and `AVWorkstationToolkit.Development` projects retain deterministic/rehearsal execution and fixed launch/root policies, but neither is referenced by `Build-Release.ps1`, embedded by the launcher, or included in EXE/MSI/ZIP composition.

Live mutation validation remains deferred because no safe eligible managed update was available. Executor/process/orchestration behavior is otherwise covered by prior real-process and deterministic validation. Phase 14 completed compiled presentation/accessibility stabilization, PowerShell-free package verification, and removal of legacy recovery files/process-policy entries. No vendor payload was executed.

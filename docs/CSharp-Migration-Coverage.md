## Active parity and integration coverage through Phase 12

The active dual-engine suite covers 19 managed planning results and 36 focused domain cases. It compares all current statuses: Current, Missing, UpdateAvailable, ManualUpdate, Held, Manual, Inventory, NotDetected, InventoryIncomplete, InventoryUnavailable, CheckUnavailable, Awareness, and Error. It also compares numeric version normalization/comparison and UI sort keys; strict catalog acceptance/rejection and authority; composed profile, priority, exact manufacturer, discipline, role, search, and Quick View filters; and None/Driver/Service/Listener behavior under clear, Windows Update, and CBS reboot states.

Phase 3 adds 37 provider cases: 9 installed-inventory, 7 update-discovery, 10 registry/detector, 4 reboot, and 7 trusted-candidate cases. Canonical comparison is strict for quality/failure classifications, normalized records, per-source availability/counts, package reliability/install/version evidence, reboot reasons, and trust disposition. A separate live read-only harness exercised WinGet resolution/export/update queries, all uninstall-registry views, and reboot signals on the validation host; local software contents are deliberately not golden data.

Phase 4 adds 4 focused presentation cases for composed filters, stable visible order, Missing/Updates selection, retained explicit selection, install/update counts, enabled state, labels, selection summary, Quick View, and reboot warning state. Compiled presentation/coordinator tests cover the larger asynchronous and failure-state surface without launching a mutation.

Phase 5 adds 4 focused read-only surface cases: three representative managed/external/awareness detail records plus one diagnostics snapshot. The comparison keeps identity, provenance, official URI metadata, explicit unknowns, status/inventory quality, catalog counts, reboot reasons, and registry-source status strict. Focused C# tests additionally cover redaction, runtime-provider failure, parent-provider relationships, malicious URI rejection, selected-detail coherence, and non-executing official URI intents.

Phase 6 adds 26 strict action-request cases. Valid Install/Update requests compare ordered and duplicate package IDs, risk acknowledgement, dry-run state, and deduplicated authorized plan IDs. Hostile cases compare semantic rejection for malformed JSON, missing/unknown/wrong-typed fields, unsupported schema, null/malformed request and package IDs, unsupported actions, empty/oversized payloads, action mismatch, held/manual/awareness/inventory-only records, risk acknowledgement, and pending-reboot risk enforcement. Request timestamps, random nonce values, temporary fixture roots, JSON whitespace, and property formatting are omitted because they are not semantic contract fields. The C# parser additionally rejects duplicate JSON property names at parse time; Windows PowerShell 5.1 `ConvertFrom-Json` retains the last duplicate, so this defense-in-depth difference is documented rather than normalized into permissive C# behavior.

Phase 7 adds 27 IPC/file-lifecycle cases covering contained request persistence meaning, canonical request/progress/result/cancel/WinGet-log identity, incremental JSONL progress, successful/failed/cancelled/dry-run final results, cancellation transitions, duplicate-final idempotence, stale/foreign identity, malformed/wrong-typed/unknown/oversized evidence, nested/wrong-extension/foreign-ID paths, and reparse rejection. Semantic output keeps acceptance, artifact kind, record/issue counts, result status, lifecycle state, cancellation state, and package IDs strict. Timestamps, temporary roots, atomic temporary names, computer identity, and JSON formatting are deliberately omitted. Focused MSTest coverage separately proves same-directory atomic write/no overwrite/no residue, bounded reads, reparse checks, split multibyte UTF-8, strict full-schema results, and illegal lifecycle transitions.

Phase 8 adds 8 focused orchestration tests and 4 process-boundary scenarios. They characterize complete-request validation, fresh authorization before every package, still-eligible execution, current/held/action/risk/reboot/unknown rejection, failure and verification-failure precedence, earlier-package effects on later eligibility, cooperative cancellation between packages, correlated progress/result artifacts, clean process exit, and final-result no-overwrite behavior. The compiled worker is intentionally stricter than shipping by refreshing the first package again after whole-request validation. The only executor is a deterministic fake; its bounded delay supports cancellation-boundary testing without launching another process. The process harness runs on a standard-user host and reports an elevated hosted runner as unavailable rather than bypassing the worker's privilege guard.

Phase 9 adds four dual-engine argument cases plus focused trust, exit, timeout, and post-action verification tests. The real executor is present only as an uncomposed Infrastructure implementation. Its public boundary accepts a typed package request, not an executable or argument list; tests inject a capturing process host and prove the trusted resolved path plus exact argument vector without launching WinGet. The Phase 8 process host remains fake-only. Fresh post-action inventory/update quality and package evidence are required before exit zero becomes verified success.

Phase 10 adds 15 deterministic vendor-boundary tests. Catalog parsing now retains the already validated delivery policy as typed data; callers cannot substitute arbitrary hosts, cache destinations, credential targets, or process arguments. HTTPS redirect handling is explicit, SFTP host identity is probed and compared before a scoped credential lookup, and downloaded payloads remain untrusted until hash/signature/publisher validation and contained promotion succeed. The concrete services are not composed into the App, worker, launcher, installer, or release build.

Phase 11 composes the compiled request, IPC, fake-worker, vendor, handoff, and diagnostics boundaries only when an explicit isolated `--migration-action-test-root` is supplied. The coordinator rejects conflicting actions, reauthorizes selection, correlates bounded progress/results, records cooperative cancellation intent, refreshes the typed plan after completion, and never terminates the independent worker on UI shutdown. The exact fake worker path is derived from the reviewed repository build location; callers cannot supply an executable or argument vector. Official browser handoffs accept only typed catalog intents, Explorer reveals only reverified cached payloads, and diagnostics copy/export uses sanitized bounded text. Normal compiled preview and the shipping launcher remain unchanged.

Phase 12 adds a separate standard-user-only `--live-rehearsal-root` composition. It accepts only a direct child of the current user's temporary directory named with the `awt-phase12-` prefix, persists a dry-run request under that isolated root, launches only the reviewed compiled worker with a fixed argument shape, composes the real trusted WinGet resolver/read-only providers and mutation executor inside that worker, releases the GUI-side process handle, recovers correlated progress/result evidence through a fresh protocol store, and refreshes current package state. The rehearsal selected an eligible catalogued package but kept `DryRun=true`; no package mutation occurred. No clearly safe managed update was available on the validation workstation, so installing unrelated software solely for rehearsal was rejected.

Phase 13 cuts the shipping bootstrap/package to the compiled WPF App, canonical production data root, hash-pinned independent compiled worker, real constrained exact-ID executor, compiled vendor/Credential Manager/cache services, diagnostics, and user handoffs. The worker is embedded as independently published bytes and extracted beneath the verified versioned runtime; test hosts and test roots do not ship. The PowerShell/WPF runtime and bridge remain only behind explicit `--legacy-powershell-recovery`, with no automatic fallback.

Live mutation validation deferred because no safe eligible managed update was available. Executor/process/orchestration behavior is otherwise covered by prior real-process and deterministic validation. Phase 14 remaining work is interactive DPI/accessibility/long-name and recovery stabilization, an eligible single-package live mutation when available, and evidence-based removal of legacy recovery files/process-policy entries. No vendor payload is executed.
